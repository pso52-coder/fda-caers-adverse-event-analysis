## 1. 데이터 단위 — 90,786행 vs 64,517건

### 차이의 원인 **[재현됨]**

| 구조 | 값 |
|---|---|
| 전체 행 | 90,786 |
| 고유 `RA_Report #` | 64,517 |
| 신고당 평균 행 수 | 1.407 |
| 단일 행 신고 | 53,700건 |
| 다중 행 신고 | 10,817건 (37,086행) |

다중 행 신고 내부를 열어보면 원인이 분명합니다.

| 항목 | 신고 내에서 값이 2종 이상인 비율 |
|---|---|
| 제품명 | **99.7%** |
| 제품 역할(Suspect/Concomitant) | 62.8% |
| 산업군 | 25.0% |
| **부작용 결과(outcomes)** | **0.0%** |

**한 신고에 여러 제품이 등록되면 그 수만큼 행이 늘어나고, `outcomes` 는 모든 행에 그대로 복제됩니다.** 부작용 결과가 신고 단위로 부여된다는 뜻입니다.

따라서 행 단위 집계는 **제품을 여러 개 신고한 사례를 그만큼 중복 반영**합니다. 제품이 6개 등록된 신고 1건은 사망 1건이 아니라 6건으로 계산됩니다.

| 원본 셀 | 그래프 | 집계 단위 | 분모 |

### Suspect / Concomitant **[재현됨]**

원본은 두 역할을 구분하지 않고 전부 사용했습니다.

| 기준 | 관측 수 | 심각 | 비율 |
|---|---|---|---|
| 행 기준 (원본) | 90,786 | 21,966 | **24.20%** |
| 고유 신고 기준 | 64,517 | 12,720 | **19.72%** |
| Suspect 행 기준 | 74,558 | 17,192 | 23.06% |

행 기준과 신고 기준의 차이가 **4.48%p** 입니다. Suspect 한정 여부보다 **행/신고 단위 선택이 결과에 훨씬 크게 작용**합니다.

## 2. 전처리 재현

### 연령 단위 통일 **[재현됨]**

원본 `convert_age()` 를 그대로 실행한 결과가 보고서 수치와 **완전히 일치**합니다.

| 연령대 | 재현값 | 보고서 | 일치 |
|---|---:|---:|:---:|
| 영유아(0-5) | 2,964 | 2,964 | O |
| 청소년(6-19) | 3,007 | 3,007 | O |
| 성인(20-59) | 26,045 | 26,045 | O |
| 노인(60+) | 20,890 | 20,890 | O |
| 합계 | 52,906 | 52,906 | O |

연령 유효 52,906행은 전체의 58.3%입니다. 나머지 37,880행은 `Not Available` 등으로 제외됩니다. **연령 관련 그래프의 분모가 전체가 아니라는 점**이 보고서에 명시돼 있지 않습니다.

### 점검 항목 4가지

**① Day(s) → 0세 처리** **[불일치 소지]**

```python
if unit == 'Day(s)':
    result = 0        # 값과 무관하게 0
```

147행이 해당하며 전부 0세가 됩니다. 생후 300일도 0세입니다. 영유아 구간(0-5) 안에 머무르므로 4구간 집계 결과는 바뀌지 않지만, 연령을 연속값으로 쓰면 왜곡됩니다.

**② 정수 절삭의 비일관성** **[불일치 소지]**

`Week(s)` 와 `Month(s)` 만 `int()` 로 절삭하고 `Year(s)` 는 절삭하지 않습니다. 11개월 아기는 `int(11/12)` = 0세가 되지만, 소수점이 있는 Year 값은 그대로 유지됩니다. 단위에 따라 처리 규칙이 다릅니다.

**③ pd.cut 경계** **[불일치]**

원본은 연령 구간을 **두 곳에서 서로 다르게** 정의합니다.

| | cell 10 (함수) | cell 13 (pd.cut) |
|---|---|---|
| 사용처 | 파이 차트(cell 19) | 스택바(cell 13) |
| 방식 | `<=5 / <=19 / <=59 / else` | `bins=[0,6,20,60,120]` |
| 영유아 | 2,964 | **2,007** |
| 청소년 | 3,007 | 3,058 |
| 성인 | 26,045 | 26,692 |
| 노인 | 20,890 | 19,937 |
| 합계 | 52,906 | **51,694** |

`pd.cut` 은 기본값 `right=True` 이므로 구간이 `(0,6]` 입니다. **0세 1,212행이 어느 구간에도 속하지 않고 탈락**하며, 6세는 영유아로, 20세는 청소년으로, 60세는 성인으로 각각 한 칸씩 밀립니다.

즉 **파이 차트와 스택바가 서로 다른 연령 정의를 쓰고 있습니다.** 같은 발표 자료 안에서 "영유아"가 2,964명이기도 하고 2,007명이기도 합니다.

**④ '노인(66+)' 오표기** **[불일치]**

cell 13의 라벨이 `노인(66+)` 인데 실제 구간은 `(60,120]` 입니다. 66은 근거 없는 숫자이며 60의 오타로 보입니다. 스택바 범례에 그대로 노출됩니다.

### 더 엄밀한 연령 환산 기준 (개선안)

원본 결과를 보존한 채 별도로 제안합니다.

```python
per_year = {'Day(s)':365.25, 'Week(s)':52.18, 'Month(s)':12.0,
            'Year(s)':1.0, 'Decade(s)':0.1}
y = age / per_year[unit]        # 절삭 없음

pd.cut(y, bins=[0, 6, 20, 60, 120.000001],
       labels=['영유아(0-5)', '청소년(6-19)', '성인(20-59)', '노인(60+)'],
       right=False, include_lowest=True)
```

구간 경계에 `right=False` 를 사용해 **라벨과 실제 경계를 일치**시킵니다. `right=True` 를 쓰면 6세가 영유아, 20세가 청소년, 60세가 성인으로 분류되어 라벨과 어긋납니다.

경계 동작 확인

| 입력 | 분류 |
|---|---|
| 0세 · 5.5세 | 영유아(0-5) |
| 6세 · 19.9세 | 청소년(6-19) |
| 20세 · 59.9세 | 성인(20-59) |
| 60세 · 120세 | 노인(60+) |

**결과** — 연속 환산값은 **1,544행**에서 달라지지만(Month 1,236 / Week 174 / Day 134), **4구간 집계는 원본과 완전히 동일**합니다.

| 구간 | 원본 | 개선 | 차이 |
|---|---:|---:|---:|
| 영유아(0-5) | 2,964 | 2,964 | 0 |
| 청소년(6-19) | 3,007 | 3,007 | 0 |
| 성인(20-59) | 26,045 | 26,045 | 0 |
| 노인(60+) | 20,890 | 20,890 | 0 |

즉 이 데이터에서는 **연령 환산 방식을 개선해도 연령대 분류 결과가 바뀌지 않습니다.** 개선의 실익은 연속 연령값을 쓰는 분석(예: 연령 분포, 상관 분석)에 한정됩니다. 발표 자료의 4구간 수치는 그대로 사용할 수 있습니다.

## 3. 심각 부작용 정의 — 43.9%의 정체

### 기존 정의 재현 **[재현됨]**

```python
any(k in outcome for k in ['DEATH', 'HOSPITALIZATION', 'LIFE THREATENING'])
```

**21,966행 / 90,786행 = 24.20%** — 지시서 기대값과 정확히 일치합니다.

### outcome 어휘 실측

CAERS의 `AEC_One Row Outcomes` 에 실제로 등장하는 항목은 12종입니다. 결측은 0건입니다.

| 항목 | 행 수 | 비율 |
|---|---:|---:|
| OTHER SERIOUS (IMPORTANT MEDICAL EVENTS) | 36,837 | 40.58% |
| NON-SERIOUS INJURIES/ ILLNESS | 27,835 | 30.66% |
| VISITED A HEALTH CARE PROVIDER | 20,158 | 22.20% |
| HOSPITALIZATION | 16,908 | 18.62% |
| VISITED AN ER | 12,890 | 14.20% |
| LIFE THREATENING | 5,274 | 5.81% |
| SERIOUS INJURIES/ ILLNESS | 3,606 | 3.97% |
| REQ. INTERVENTION TO PRVNT PERM. IMPRMNT. | 2,944 | 3.24% |
| DISABILITY | 2,890 | 3.18% |
| DEATH | 2,028 | 2.23% |
| NONE | 145 | 0.16% |
| CONGENITAL ANOMALY | 77 | 0.08% |

### 43.9%가 나온 경로 **[불일치]**

도넛 차트(cell 18)는 다음을 계산합니다.

| 슬라이스 | 코드 | 행 수 | 도넛 비율 |
|---|---|---:|---:|
| 사망 | `contains('DEATH')` | 2,028 | 1.7% |
| 생명위협 | `contains('LIFE THREATENING')` | 5,274 | 4.3% |
| 입원 | `contains('HOSPITALIZATION')` | 16,908 | 13.8% |
| 응급실 | `contains('EMERGENCY')` | **0** | — |
| 병원방문 | `contains('DOCTOR\|VISIT')` | 29,652 | 24.2% |
| 비심각 | `serious == False` | 68,820 | 56.1% |
| **합계(분모)** | | **122,682** | 100% |

**심각 슬라이스 합 = 100 − 56.1 = 43.9%** — 보고서 수치가 정확히 재현됩니다.

문제는 세 가지입니다.

**첫째, 분모가 행 수가 아닙니다.** 슬라이스 합계 122,682는 전체 90,786행보다 **31,896 많습니다.** 한 신고가 입원과 병원방문을 동시에 가지면 두 번 계산되기 때문입니다. 비율의 분모로 쓸 수 없는 값입니다.

**둘째, 팀 자체 정의와 모순됩니다.** `serious` 는 사망·입원·생명위협 3종으로 정의했는데, 도넛은 여기에 **병원방문 29,652행을 추가**했습니다. 43.9% 중 24.2%p가 이 항목입니다. 팀 스스로 심각으로 분류하지 않은 것이 심각 비율의 절반 이상을 차지합니다.

**셋째, '응급실' 슬라이스는 존재하지 않습니다.** `'EMERGENCY'` 로 검색했으나 실제 표기는 `VISITED AN ER` 이라 매칭이 0건입니다. `data_counts[data_counts > 0]` 필터에서 조용히 사라져 그래프에 나타나지 않습니다. 한편 `'DOCTOR|VISIT'` 은 `VISITED AN ER`(12,890)과 `VISITED A HEALTH CARE PROVIDER`(20,158)를 **둘 다** 잡아 29,652행이 됩니다. 응급실 방문이 '병원방문'에 흡수된 것입니다.

### 중복 없는 재계산

| 방식 | 값 | 설명 |
|---|---:|---|
| 행 단위 심각도 | **24.20%** | 21,966 / 90,786 |
| 신고 단위 심각도 | **19.72%** | 12,720 / 64,517 |
| 개별 outcome 보유율 | 각각 별도 | 합이 100%를 넘음 (중복 허용) |

### "전체 신고 중 43.9%가 심각 부작용" — 사용 가능 여부

**사용할 수 없습니다.** 세 가지 이유가 겹칩니다.

1. 분모(122,682)가 신고 수도 행 수도 아닌 중복 합산값입니다
2. 팀 자체 serious 정의에 없는 병원방문이 포함됐습니다
3. "전체 신고 중"이라고 했으나 실제 단위는 신고가 아니라 행이며, 그마저 중복 계산됐습니다

**대체 문장** — 어느 쪽이든 단위를 명시해야 합니다.

> 전체 **신고** 64,517건 중 19.7%가 사망·입원·생명위협을 동반했다.
> 전체 **행** 90,786건 중 24.2%가 사망·입원·생명위협을 동반했다.

병원방문까지 포함하려면 정의를 바꾸고 다시 계산해야 하며, 그 경우에도 중복 없는 행/신고 단위로 산출해야 합니다.

**참고** — FDA CAERS 자체 기준의 serious 범주는 팀 정의보다 넓습니다(DISABILITY, CONGENITAL ANOMALY, REQ. INTERVENTION, OTHER SERIOUS 등 포함). 팀 정의는 좁은 축에 속하며, 그 자체가 틀린 것은 아니지만 **"심각"이라는 단어의 범위를 README에 명시**해야 합니다.

순위도 바뀝니다. 행 기준 10위 `Vegetable Oils` 가 빠지고 `Beverage Bases/Conc/Nectar` 가 들어옵니다.

**결론** — "45.1%"라는 수치 자체는 재현되지만, **행 기준임을 명시해야** 합니다. 명시 없이 쓰면 "신고 100건 중 45건이 심각"으로 읽히는데 실제로는 40.9건입니다.

### 통계적 이상치 탐지 로직 — 존재하지 않음 **[불일치]**

보고서는 다음과 같이 기술합니다.

> Vit/Min 산업군 내 브랜드별 심각 부작용 비율 분석 중 **통계적 이상치 브랜드 발견**

**코드에 이상치 탐지 알고리즘이 없습니다.** cell 16~17에서 브랜드에 적용되는 연산은 네 가지뿐입니다.

1. `query('total >= 20')` — 표본 하한
2. `nlargest(80, 'total')` — 신고량 상위 80개
3. `axvline/axhline(median)` — 중앙값 보조선. **그려지기만 하고 어떤 필터에도 사용되지 않음**
4. `주요브랜드 = [...]` — 라벨 표시용 **하드코딩 목록 6~7종**

### 당시 실제 선별 방식 (기록)

사례 심층 분석(옥시엘리트프로·하이드록시컷)은 팀 분석 단계 종료 후 본인이 개인적으로 추가 수행한 작업이며, 역할표에는 반영되지 않았습니다. **절차는 본인 확인을 거쳐 다음과 같이 확정합니다.**

| 단계 | 방법 |
|---|---|
| 1. 브랜드 선별 | 브랜드별 신고 건수 × 심각 비율 산점도에서 **우상단 영역을 육안으로 판별** |
| 2. 추이 확인 | 선별 브랜드의 연도별 신고 건수 추이 작성 |
| 3. 급증 시기 특정 | 추이 그래프에서 **급증 구간을 육안으로 판별** |
| 4. 외부 대조 | 해당 시기의 규제기관 조치·보도자료 검색 후 시점 대조 |

1·3단계 모두 통계적 기준이 아니라 **그래프를 눈으로 확인해 판단**하는 방식입니다. 탐색적 분석에서 통상적인 접근이며 방법 자체에 문제는 없습니다. 다만 이를 "통계적 이상치 탐지"라고 표현할 수는 없습니다.

**이 작업의 코드는 제출된 노트북에 포함돼 있지 않습니다.** 브랜드별 연도별 추이를 그리는 셀이 존재하지 않으며, 분석 단계 종료 후 별도 수행했다는 진술과 일치합니다. 아래는 제출된 노트북(cell 16~17)에 남아 있는 브랜드 선별 코드만을 근거로 한 기록입니다.

1. 신고량 상위 80개 브랜드 산점도를 그림
2. 중앙값 보조선으로 사분면을 시각적으로 구분
3. **눈으로 보아 우상단에 위치한 브랜드를 사람이 선택**
4. 선택한 이름을 `주요브랜드` 리스트에 직접 입력해 라벨 표시
5. 그중 2종(OXYELITE PRO, HYDROXYCUT)을 심층 사례로 서술

이는 **시각적 탐색 기반 사례 선정**이며, 그 자체로 부적절한 방법은 아닙니다. 문제는 이것을 "통계적 이상치 탐지"라고 표현한 점입니다.

### 제품명 분산 문제 **[불일치]**

아래 통합은 **문자열 패턴 기반 브랜드군 통합**입니다. 공인 브랜드 사전이 아니라 제품명에 특정 문자열이 포함되는지만 확인하는 규칙 기반 처리이며, 표기가 크게 다르면 누락되고 다른 브랜드가 같은 문자열을 포함하면 과대 포함될 수 있습니다. **기존 분석의 표본 누락 규모를 확인하는 감사 목적**으로만 사용하며, 새로운 주 분석의 집계 단위로 삼지 않습니다.

전체 고유 제품명 45,685종. 브랜드 하나가 여러 이름으로 흩어져 있습니다.

| 브랜드군 | 기존 사용 제품명 | 기존 행수 | 기존 비율 | 통합 후 행수 | 통합 후 비율 | 매칭 제품명 수 | 배율 |
|---|---|---:|---:|---:|---:|---:|---:|
| HYDROXYCUT | `HYDROXYCUT` | 171 | 55.0% | **1,300** | **37.5%** | 245 | 7.6배 |
| OXYELITE | `OXYELITE PRO` | 79 | 59.5% | 158 | 57.6% | 39 | 2.0배 |

**HYDROXYCUT의 영향이 가장 큽니다.** 실제 1,300행 중 171행(13.2%)만 분석에 반영됐고, 나머지는 `HYDROXYCUT REGULAR RAPID RELEASE CAPLETS`(327행), `HYDROXYCUT HARDCORE CAPSULES`(132행) 등 244개 이름으로 흩어져 각각 20행 미만이라 필터에서 탈락했습니다.
